    Expedientes

    Bugs difíciles, resueltos con evidencia

    Casos reales de estos proyectos. No asumo, demuestro: cada hipótesis se confirma o se descarta con una prueba.

    Defecto de producto Los cuartos nuevos nunca aparecían en el inicio Playwright · TypeScript
    1. Síntoma El test "un cuarto creado por API aparece en el inicio" fallaba en Chromium, Firefox y WebKit.
    2. Hipótesis ¿Caché del navegador o del servidor? ¿Mi test buscaba mal la tarjeta?
    3. Prueba Intercepté la red: la página recibía 4 cuartos de /api/room pero solo pintaba 3. Busqué en el JavaScript publicado.
    4. Causa El frontend hace rooms.slice(0, 3): los cuartos a partir del cuarto nunca se ofrecen a los huéspedes.
    5. Resultado BUG-001 documentado con evidencia y un test @known-defect; el chequeo híbrido ahora compara las tarjetas con la API.
    Reporte en vivo ↗
    Test intermitente La búsqueda pasaba una vez y luego fallaba siempre FHIR · C#
    1. Síntoma "Buscar paciente por apellido y fecha de nacimiento" pasaba en la primera corrida y fallaba en todas las siguientes.
    2. Hipótesis El servidor HAPI FHIR reutiliza resultados de búsquedas idénticas recientes.
    3. Prueba Lo reproduje con curl: creé un paciente y la misma búsqueda no lo devolvía; con Cache-Control: no-cache sí aparecía.
    4. Causa Caché de búsquedas del servidor: comportamiento documentado de HAPI, no un defecto, pero oculta datos recién creados.
    5. Resultado El cliente envía Cache-Control: no-cache en cada búsqueda → 14 corridas seguidas en verde.
    Reporte en vivo ↗
    Entorno Chrome se tragaba los clics Java · Selenium
    1. Síntoma El carrito quedaba en 0 tras agregar productos y el menú de logout nunca abría. Solo en Chrome.
    2. Hipótesis ¿Locators incorrectos tras un cambio del sitio?
    3. Prueba Volqué todos los atributos data-test de cada página: todos los locators existían. La hipótesis quedó descartada.
    4. Causa Las credenciales públicas de SauceDemo disparan el aviso "contraseña filtrada" de Chrome, que bloquea la página.
    5. Resultado Gestor de contraseñas y detección de filtraciones desactivados con preferencias de Chrome en el DriverFactory.
    Reporte en vivo ↗
    Test intermitente StaleElementReferenceException al quitar del carrito Java · Selenium
    1. Síntoma Un escenario fallaba de forma intermitente con StaleElementReferenceException.
    2. Hipótesis React vuelve a dibujar la lista entre que Selenium encuentra la fila y le hace clic.
    3. Prueba El stack trace apuntaba a la búsqueda del producto dentro del carrito, justo después de navegar.
    4. Causa Referencias a elementos que React ya había reemplazado.
    5. Resultado Búsqueda y clic reintentados juntos ignorando elementos obsoletos, y espera a que la lista tenga un elemento menos → 8 corridas en verde.
    Reporte en vivo ↗
    Test intermitente Un null aleatorio rompía la validación .NET · C#
    1. Síntoma "Crear una reserva" fallaba a veces en la validación de esquema JSON.
    2. Hipótesis Los datos aleatorios generan un caso que el esquema no acepta.
    3. Prueba El error del esquema señalaba el campo exacto: /additionalneeds: Value is "null" but should be "string".
    4. Causa El generador a veces enviaba additionalneeds: null y la API lo devolvía igual.
    5. Resultado El campo opcional se omite en vez de enviarse como null. Verificado forzando el caso en los 21 escenarios y con 37 corridas repetidas.

    Cómo trabajo

    Calidad que se puede demostrar

    01

    Arrange por API, prueba por UI

    Los datos se crean y verifican por API: pruebas rápidas, independientes y que confirman lo que de verdad se guardó.

    02

    Una prueba debe poder fallar

    Antes de confiar en un test verde, rompo a propósito lo que verifica. Si no falla, no está probando nada.

    03

    Defectos visibles, no escondidos

    Un bug conocido se documenta con evidencia y su propio test, que falla a propósito cuando se corrige.

    04

    Trazabilidad de punta a punta

    Requisito → escenario → defecto. En salud aprendí que la calidad es poder demostrar qué se probó y por qué.
